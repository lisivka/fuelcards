## [0.10.0] — 2026-11-11
### Додано
- «Карти»: масова зміна типу авто або менеджера. Відфільтруйте картки, відмітьте потрібні галочками (у заголовку — «відмітити всі видимі»), на панелі «Відмічено: N» виберіть тип авто чи менеджера (або «зняти») і натисніть «Змінити…»; після підтвердження з'явиться повідомлення, скільки карток змінено, а скільки вже мали це значення. Лише в нашій базі, у провайдера не пишеться; кожна змінена картка — у журналі аудиту. Відмітки з карток, прихованих фільтром, знімаються автоматично.
### Деплой
- Без міграцій, нових змінних `.env` і залежностей — звичайний `deploy.sh`. Викладено на сервер 2026-11-11. Тег `v0.10.0` — на коміт злиття ЗАДАЧІ-18 у `master` (`8c82a7a`).

## [0.5.0] — 2026-11-04
### Додано
- Блокування/розблокування карток Petroline через API (сторінка картки і «Карти»): спершу запит у Petroline, потім база й журнал аудиту.
- Авто/ПІБ карток Petroline змінюються і в Petroline (сторінка картки): персональна — перейменування її водія на «Авто | ПІБ», техпролив — лише ПІБ. Автомобільна картка і картка без водія зберігаються лише в нас; кнопка «Зберегти і записати в Petroline» робить її «Персональною» на наявному водієві з таким самим ім'ям (нова картка замість загубленої) або створює водія. Перед записом — підтвердження «було → стане».
- Сторінка картки Petroline: тип картки, водій (id), дата останнього оновлення; якщо наші Авто/ПІБ не збігаються з Petroline — обидва варіанти і кнопки «Взяти з Petroline» (лише база) / «Записати наше в Petroline».
- «Карти»: тип картки Petroline, позначка «≠ у Petroline» і фільтр «Розбіжності з Petroline».
- Спільний водій Petroline (кілька карток на одного водія): постійне попередження з переліком карток на сторінці картки, підтвердження перед збереженням, сторінка «Дублі водіїв» (кнопка на «Картах»). Зміна Авто/ПІБ застосовується до всіх карток водія.
### Змінено
- На сторінці «Карти» Авто/ПІБ карток Petroline редагуються лише на сторінці картки.
- «Оновити карти Petroline»: Авто/ПІБ заповнюються лише для карток, де обидва порожні (ім'я без «|» — в Авто), інакше розбіжність показується користувачу.
- Транзакції Petroline з пальним «Вода» не завантажуються.
- Сторінка «Логи» (пункт меню, усім авторизованим): журнал аудиту — зміни карток і синхронізації; фільтри «Дія», «Постачальник», «Лише помилки» (запам'ятовуються в браузері), по 20 записів на сторінку, посилання на сторінку картки.
- Журнал аудиту записує синхронізації: транзакцій (кнопка на «Транзакціях», дії адмінки, `sync_fuel`) і карток (кнопки на «Картах», `sync_cards`) — хто запустив (для команд «система»), період, нових/оновлено, частини, помилки. Один запис на провайдера за запуск; неактивні провайдери не записуються.
- `sync_cards --provider petroline|ukrnafta` (типово ukrnafta).
- Транзакції Petroline завантажуються з нового API (`apiv2.petroline.in.ua`, `TrkTransactions/v2/list`) з пагінацією; той самий вхід, що й для карток. ID транзакцій збігаються зі старим API, тож дублікатів не буде. У полі водія/авто новий порядок слів («KI 68-02 AC» замість «68-02 AC KI»).
- `sync_cards` пропускає неактивного провайдера з помилкою, як і решта синхронізацій.
### Деплой
- Міграція `0009` (поля прив'язки картки у провайдера; не деструктивна, відкат — `migrate fuel 0008`). Після деплою (до цього Авто/ПІБ карток Petroline у Petroline не пишуться — тип невідомий): резервна копія бази → в адмінці видалити всі картки Petroline (транзакції не видаляти — синхронізація оновлює їх за ID) → одразу «Оновити карти Petroline» (до цього не запускати синхронізацію транзакцій, інакше вона створить картки без типу) → повна пересинхронізація транзакцій Petroline з 20.07.2026 (відновить зв'язок транзакцій з картками).
- Блокування Petroline вмикається галочкою «Можна змінювати картки» в «Конфігурації провайдера» (типово ввімкнена): після деплою кнопка для Petroline стане активною одразу. Щоб вимкнути — зняти галочку.
- Нова необов'язкова змінна `.env`: `PETROLINE_API` (порожньо — новий API; `legacy` — повернутись до старого). Для нового API потрібен звичайний пароль у `PETROLINE_V2_PASSWORD` або `PETROLINE_PASS` (не SHA256).
- Після деплою (з дозволу) — повна пересинхронізація Petroline (`sync_fuel --config-period --provider petroline` за весь період), щоб у всіх транзакціях був однаковий порядок слів у полі водія.
- Міграція `0008_auditlog_sync` (поле `details` у журналі аудиту й нові типи дій; не деструктивна, відкат — `migrate fuel 0007`).

## [0.4.0] — 2026-11-03
### Додано
- Сторінка картки (`/cards/<id>/`): відкривається кліком на номер картки в «Транзакціях» і «Картах». Інформація, редагування Авто / ПІБ / Примітки (для UkrNafta Авто і ПІБ змінюються у провайдера, для Petroline і UPG — лише в базі), кнопка «Заблокувати / Розблокувати» з підтвердженням (лише UkrNafta), останні 20 транзакцій, журнал змін картки.
- Журнал аудиту (`AuditLog`): хто, коли й що змінив у картці (створення, Авто/ПІБ/Примітка, статус, видалення), чи йшло через API і чи вдалося — невдалі спроби запису в API теж фіксуються. Перегляд: сторінка картки та Адмінка → «Журнал аудиту» (лише читання).
- Сторінка «Транзакції»: кнопки швидкого періоду «Сьогодні / Вчора / 7 днів / 30 днів» (період відносний: збережений «7 днів» завтра покаже нові 7 днів); решта фільтрів при цьому не змінюється.
- Сторінка «Транзакції»: звіт (період, фільтри, сторінка, к-сть рядків) запам'ятовується в браузері — повернення з «Карт» чи через меню відкриває той самий звіт; кнопка «Скинути фільтри».
- Сторінка «Транзакції»: список «Рядків» (25/50/100/200/500) після «Експорт CSV».
- Адмінка → «Конфігурації провайдерів»: дії «Синхронізувати вибраних за N днів» і «… за період з/по»; у конфігурації нові поля «Глибина синхронізації, днів», «Синхронізувати з», «Синхронізувати по». Після запуску адмінка показує: кого пропущено (неактивні, не задано період), на скільки частин розбито період, результат кожної частини і помилки.
- `sync_fuel`: ключі `--config-days` і `--config-period` (глибина/період з конфігурації провайдера); при неправильних аргументах команда показує приклади запуску.
- Сторінка «Карти»: кнопка «Оновити карти Petroline» — підтягує картки з нового API Petroline (лише читання): номер на картці, ID, статус, назву водія/авто.
- Картка має «Номер на картці» (`ext_number`) і «ID у провайдера» (`external_id`); для Petroline ключем зв'язку з транзакціями лишається «Ідентифікатор».
- Сторінка «Карти»: швидкий перемикач «Всі / Активні / Неактивні» (неактивні — усі, крім статусу «Активна»).
- Сторінка «Транзакції»: колонка «Ідентифікатор» (за замовчуванням прихована), у колонці «Картка» — номер на картці; пошук за обома номерами; те саме в експорті CSV.
### Виправлено
- Сторінка «Транзакції»: кнопка «Синхронізувати» знову зелена і стоїть першою, перед «Колонки ▾»; розмір збігається з іншими кнопками.
### Змінено
- Сторінка «Транзакції»: пагінація з номерами сторінок `← 1 2 3 … 9 [10] 11 … 20 21 22 →`.
- Синхронізація за період понад 30 днів (`sync_fuel`, дії адмінки) іде частинами по 30 днів з паузою 2 с між запитами; максимальний період — 366 днів. Помилка в частині зупиняє решту частин лише цього провайдера.
### Деплой
- Обов'язково `python manage.py migrate` — у версії нові міграції (усі не деструктивні):
  - `0004_card_ext_number_external_id` — два порожні поля картки;
  - `0005_providerconfig_row_color` — колір рядків провайдера;
  - `0006_providerconfig_sync_period` — глибина й період синхронізації в `ProviderConfig`;
  - `0007_auditlog` — нова таблиця журналу аудиту.
- Перед `migrate` на сервері: `python manage.py showmigrations fuel` — остання застосована міграція і є точкою відкату (за журналом змін очікується `0003_alter_card_status`).
- Відкат версії: спершу `python manage.py migrate fuel <точка відкату>` (поки код ще новий), потім повернути код на попередній коміт. Тегу `v0.3.0` у репозиторії немає.
- Після деплою: поставити тег `git tag v0.4.0 && git push --tags`.
- `.env`: для нового API Petroline потрібен звичайний (не SHA256) пароль — `PETROLINE_V2_LOGIN`/`PETROLINE_V2_PASSWORD` або `PETROLINE_LOGIN`/`PETROLINE_PASSWORD`. Змінна `UPG_TOKEN` більше не використовується.
