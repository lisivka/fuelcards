## 📋 Заплановано
- ЗАДАЧА-4б — редагування лімітів (перевірка запису на тестовій картці — з дозволу; формати запису UkrNafta і поля Petroline — у `PROJECT.md`; з'ясувати: що означає `limitBalance` = 0 і значення ліміту 0 в UkrNafta, як змінювати `PersonLimit` у Petroline, чи можна фільтрувати `PersonLimit/list` за водієм). Вихідний опис ЗАДАЧІ-4: UkrNafta — ліміти на картку, API підтримує (`GET /cards/{cardId}/limits`, `POST .../limits/create`, `POST .../limits/{limitId}/update`, `DELETE .../limits/{limitId}/delete`, довідник типів `GET /common/limits/types`; формат тіл з'ясувати перевіркою) і Petroline — ліміт на водія (`PersonLimit`), див. рішення 004; спершу перегляд лімітів і залишків, потім редагування. Перевірено: `PersonLimit` у Petroline вже використовуються, значення схоже на літри (`onceLimit` 20–200, `dayLimit` 120 — підтвердити в кабінеті Petroline), `TransportLimit` порожні; з'ясувати значення `status`/`limitStatus` і `dayOffLimit = -1`
- Petroline: після першого реального перейменування водія перевірити, чи змінюється «Авто» в старих транзакціях після пересинхронізації (API віддає ім'я на момент заправки чи поточне)
- ЗАДАЧА-5 — Тести (адаптери на фікстурах, сервіс карток з моками) і ruff
- Копія щоденного бекапу на мережеву шару: код і інструкції готові (`BACKUP_REMOTE_DIR`, `deploy/SERVER_SETUP.md` 8.2); `\\public.ua\Public` для гостя без права запису (перевірено 2026-11-06) — потрібна тека з правом запису або обліковий запис від адміністратора
