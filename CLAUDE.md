# CLAUDE.md — «Рух пального» (fuelcards)

Цей файл Claude Code читає на початку кожної сесії. Тут лише правила й команди.
Опис домену, провайдерів і моделі даних — у @PROJECT.md. Поточні задачі — у @docs/TASKS.md.

## Мова і стиль спілкування
- Спілкування, коментарі в коді, повідомлення комітів, документація — **українською**.
- Ідентифікатори в коді (змінні, функції, класи) — англійською.

## Порядок роботи (обов'язковий)
1. **Спершу план.** Перед будь-якою зміною коду коротко опиши: що змінюю, у яких файлах, як перевірю, які ризики. Чекай підтвердження.
2. **Одна задача — одна гілка** `task/<N>-<коротко>` від `main`. Ніколи не коміть напряму в `main`.
3. **Малі кроки.** Після кожного логічного кроку: тести + ruff, потім покажи підсумок змін.
4. **Не вигадуй.** Якщо формат відповіді API провайдера, поле моделі чи поведінка невідомі — спитай або подивись у код/збережені відповіді, не здогадуйся.
5. **Завершення задачі** = зелені тести + `ruff check` без помилок + `ruff format --check` без змін + оновлені `docs/TASKS.md`, `CHANGELOG.md` і, якщо змінилась логіка, `PROJECT.md`.

## Формат коду у відповідях
- Цілі файли або чіткі diff-патчі. Без обірваних шматків на кшталт «тут ваш код».

## Команди (Windows, з активованим `.venv`)
```
python manage.py runserver                 # локальний сервер
python manage.py check                     # перевірка конфігурації
python manage.py makemigrations --check --dry-run   # чи є незроблені міграції
python -m pytest                           # тести (fuel/tests/)
python -m ruff check .                     # лінтер
python -m ruff format .                    # форматування
python -m ruff format --check .            # перевірка форматування (має бути без змін)
python manage.py sync_fuel --days 2        # синхронізація (ходить у РЕАЛЬНІ API — лише з дозволу)
```

## Структура
- `config/` — налаштування Django; `fuel/` — єдиний застосунок.
- `fuel/providers/` — адаптери провайдерів; усі повертають `NormalizedTx` (`base.py`).
- `fuel/services.py` — upsert і синхронізація; `fuel/card_service.py` — керування картками.
- `fuel/tests/` — тести; `fuel/tests/fixtures/` — збережені (знеособлені) відповіді API.
- `scripts/probes/` — ручні скрипти перевірки API провайдерів (не тести, тут не запускати).
- `deploy/` — systemd-юніт, `deploy.sh`, інструкція для сервера.
- `docs/` — задачі, рішення, правила роботи.

## Жорсткі обмеження
- **Секрети:** ніколи не читай і не виводь `.env`; нові змінні додавай лише в `.env_example` з порожнім значенням.
- **Реальні API провайдерів:** у тестах — тільки моки та фікстури. Запуск `sync_fuel`, `sync_cards`, скриптів з `scripts/probes/` і будь-який запис у API (блокування карток, ліміти) — лише після явного дозволу в чаті.
- **Збій одного провайдера не зупиняє інших.** Помилки логуються (`logging`), не `print`.
- **Сервер (192.168.1.173) — не твоя зона.** Жодних `ssh`, `scp`, деплою, зміни продакшн-бази. Деплой робить людина через `deploy/deploy.sh`.
- **Міграції:** кожну нову міграцію покажи й поясни; деструктивні (видалення полів/таблиць, зміна типів) — лише з окремим підтвердженням і планом відкату.
- **База:** `db.sqlite3` не редагувати вручну і не комітити.
- **Залежності:** нову бібліотеку додавати лише після обговорення; фіксувати в `requirements.txt` (прод) або `requirements-dev.txt` (розробка).

## Технічні стандарти
- Python 3.10 (як на сервері): не використовуй синтаксис 3.11+.
- Django 5.x, SQLite (WAL, `transaction_mode=IMMEDIATE`), часова зона `Europe/Kyiv`, `USE_TZ=True` — дати завжди aware.
- PEP 8 / ruff; функції з type hints; довгі функції — розбивати.
- Синхронізація ідемпотентна: повторне завантаження оновлює записи, а не дублює.
- Записи в API провайдерів: спочатку API, у базу — лише після успіху; дія має бути простежувана (журнал аудиту).
